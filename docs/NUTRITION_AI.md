# 식사 기록 및 AI 설명 (2026-11-07)

## 사용 순서

1. **식사 기록·AI → 음식 등록·영양 정보 수정**에서 음식 이름, 출처, 100g당 열량·단백질·탄수화물·지방을 입력합니다.
2. 등록한 음식을 검색하고 날짜·끼니·섭취량(g)을 저장합니다. 합계는 입력한 음식에 대해서만 계산됩니다.
3. 기록 수정에서 날짜·끼니·섭취량을 변경하거나 확인 후 삭제합니다. 잘못된 음식 선택은 삭제 후 재등록합니다.
4. **오늘의 추천 · AI**에서 오늘의 시간·피로도·통증 여부를 선택합니다.
5. **식사 가이드**에서 저장한 제외 재료·알레르기·선호 조건을 통과한 식사 후보와 기존 운동 추천을 함께 확인합니다.
6. AI 연결 영역에 API 키와 계정에서 사용 가능한 Responses API 모델 ID를 입력하고, 전송 내용을 검토·동의한 뒤 설명을 요청합니다.

API 키는 채팅이나 GitHub에 올리지 마세요. 프로그램의 암호 입력칸에만 입력하며 DB에 저장하지 않습니다.
탭 전환 또는 앱 종료 시 다시 입력해야 할 수 있습니다. 외부 API는 인터넷과 별도 이용 비용이 필요합니다.
이 구현은 OpenAI Responses API에 store=false로 요청합니다. 이것이 제공자의 모든 보관 정책을 제거한다는 뜻은 아닙니다.
참고: https://developers.openai.com/api/docs/guides/text

## 계산과 추천의 범위

- 합계 = 식품의 100g당 수치 × 섭취량/100. 식품 정보를 수정해도 기존 식사 기록의 수치는 바뀌지 않습니다.
- 식품 데이터는 사용자가 등록한 표시값이며, AI가 음식 영양 수치를 추정하지 않습니다. 사진 인식과 외부 식품 DB 검색은 미구현입니다.
- 기본 후보는 목표·최근 운동·기구·제외 조건과 현재 입력한 컨디션으로 선택합니다. 식사 영양 합계에 따른 자동 처방은 하지 않습니다.
- AI는 오늘 입력한 음식 이름·영양 합계·운동 목표·시간·피로·통증 여부 및 필터링된 후보를 전달받아 설명합니다. 신체 수치, 원본 DB, API 키는 입력 본문에 넣지 않습니다.
- 통증·높은 피로도 또는 10분 미만인 경우 기본 운동 후보를 숨기는 보수적 제품 규칙입니다. 의료적 운동 가능 여부 판정이 아닙니다.
- 부족/과잉 열량 판정, 칼로리를 상쇄하는 운동, 개인별 영양소 목표 계산은 제공하지 않습니다.
- AI 출력은 검토용이며 자동으로 운동·식사 기록을 변경하지 않습니다. AI가 후보 밖 제안을 하는 등 오류가 날 수 있으므로 기록 추가는 검증된 후보 버튼만 사용합니다.
- API 연결 실패 시 일반 후보가 유지됩니다. 요청 내용이 바뀌면 기존 AI 답변을 지우고 다시 동의를 받습니다.

## 데모

데모 초기화 시 오늘 날짜의 **가상 식사 샘플**과 섭취 기록을 생성합니다.
이 수치는 합성 테스트용으로 실제 식품이 아닙니다. 기존 데모에 자동 삽입하지 않습니다.

## 검증 상태

영양 계산, 과거 수치 보존, CRUD, 컨디션 조건, HTTP 요청/응답 모의 테스트, Streamlit 화면 테스트를 수행했습니다.
실제 API 키가 제공되지 않아 실서비스 모델 응답·비용·품질은 아직 검증하지 않았습니다.
